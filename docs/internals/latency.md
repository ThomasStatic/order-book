# Latency harness

Implementation notes. Methodology is in [`../../benchmarks/latency/README.md`](../../benchmarks/latency/README.md), and the claims rule in [`../LATENCY.md`](../LATENCY.md).

- **Layout.** Library `order_book_latency` (`benchmarks/latency/`, linking `order_book_benchmarking` for workloads and `BuildInfo`) and program `order_book_latency_benchmarks`, both built by `ORDER_BOOK_BUILD_BENCHMARKS`. Neither is public API. The program exits 3 in an unoptimized build unless given `--allow-unoptimized`, by the same `BuildInfo::optimized()` as `order_book_benchmarks`.
- **`Histogram`** (`histogram.hpp`). 256 exact buckets, then 128 for each further doubling, `bucketCount` 7,424 in all, so it never overflows and needs no maximum. `bucketOf`, `bucketLow`, and `bucketHigh` are `constexpr`. `record` is inline. `valueAt` returns the upper edge of the bucket at the rank, clamped to the exact `maximum()`, so a percentile never understates. A `Percentile` is parts per 100,000, so `rankOf` stays in integers: 0.999 × 1,000,000 is not 999,000 in floating point.
- **`Clock`** (`clock.hpp`). `now()` branches on one bool; a timed path takes a predicted branch and no virtual call. `measureClock` calibrates over 50 ms and takes the step as the gcd of 100,000 successive differences.
- **Drivers** (`timetable.hpp`). Templates over a clock with `now()` and `spinUntil()`, so tests inject `FakeClock`, which jumps on `spinUntil`. A target is called as `target(index, clock)` and returns the closing reading itself, so tidying up stays outside the interval without the driver knowing about results. `backlogGrowing` compares the least lateness of the last two tenths of a run, which a drained burst doesn't disturb, where a mean would flag a stall near the end.
- **`CommandTarget`** (`command_target.hpp`). Keeps its result in a local past the closing reading, so destruction is untimed. `checkOutcome` compares with `Workload::expected` by the same `recordFinalBook` and `describeOutcome` as the runner, which `benchmark_runner.hpp` exposes along with `preloadBook`. It counts every submission through `countEvents`, which agrees with the runner's v1 tally since a v1 workload has no expiry, prevention, or stop.
- **`RunRecord`** (`latency_report.hpp`). A fixed field list, each starting unfilled, and `set` throws on an unknown name, so a misspelling can't leave the real field missing unnoticed. There is deliberately no default: `startRow` in `latency_main.cpp` leaves `capacity-growths` unfilled until L5.
- **`ReportRow` and `formatRow`.** A row is one interval, rate, and workload. `unquotableReasons` lists what stops it being quoted, in a fixed order. `noiseMarkFactor` (4) is chosen so the ticket's worked example comes out: at 1M commands/s, 35 to 118 gaps a second over 10 µs mark p99.99 (a tail of 100/s) and not `pending-stops`' p99.9 (1,000/s).
- **`thread_setup`**. `pinCurrentThread` and `raiseCurrentThreadPriority` throw when refused, so a record never claims a setting that didn't apply.
- **Tests.** `latency_harness_tests` takes `tests/latency` as its argument. Report cases compare with hand-written files in `tests/latency/expected/`, read in text mode so CRLF checkouts compare like LF. No test asserts a latency value: the clock case is sanity only. `latency_cli_smoke` and `latency_cli_smoke_response` run tiny closed-loop and timetable sessions with `--allow-unoptimized`.
