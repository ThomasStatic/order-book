# Testing

Test names, build options, what each suite covers, and test conventions. The other suites are in [`randomized-tests.md`](randomized-tests.md), [`replay.md`](replay.md), and [`benchmarks.md`](benchmarks.md).

## Running tests

Run a single test by CTest name with `-R` (names: `order_book_smoke`, `order_tests`, `result_type_tests`, `small_vector_tests`, `node_pool_tests`, `node_pool_poison_tests` (ASan only, Skipped elsewhere), `order_index_tests`, `price_level_tests`, `execution_tests`, `matching_tests`, `cancellation_tests`, `submission_tests`, `result_reuse_tests`, `event_tests`, `event_format_tests`, `order_behavior_tests`, `allocation_failure_tests`, `invariant_tests`, `scenario_tests`, `replay_parser_tests`, `replay_engine_tests`, `replay_cli_<sample>` (e.g. `replay_cli_basic`; `-R replay` runs all replay tests), `randomized_seeds`, `randomized_regressions`, `randomized_harness_tests`, `invariant_boundary_addOrder`/`_submitOrder`/`_cancelOrder`/`_consumeLevel`/`_cancelOrderThrows`, and, only with `ORDER_BOOK_BUILD_BENCHMARKS=ON`, `benchmark_harness_tests`, `benchmark_cli_smoke`, `latency_harness_tests`, `latency_cli_smoke`, `latency_cli_smoke_response`, and `component_cli_smoke`), e.g. `ctest --test-dir build -C Debug -R price_level_tests --output-on-failure`, or build and run one target directly (`cmake --build build --config Debug --target price_level_tests`).
CMake options: `ORDER_BOOK_BUILD_BENCHMARKS`, `ORDER_BOOK_ENABLE_ASAN` (GCC/Clang/MSVC; on MSVC it strips `/RTC1` from Debug flags and copies `clang_rt.asan_dynamic-*.dll` next to each executable), `ORDER_BOOK_ENABLE_UBSAN` (GCC/Clang only, with `-fno-sanitize-recover` so a finding fails the test; ignored with a warning on MSVC), `ORDER_BOOK_WARNINGS_AS_ERRORS`, `ORDER_BOOK_INVARIANT_CHECKS` (`AUTO`, the default, checks the whole book after each public command only where `NDEBUG` is undefined, i.e. Debug; `ON` or `OFF` defines the macro of the same name as 1 or 0, PUBLIC, for every configuration).

## What each suite covers

- `execution_tests` drives single `executeOnce` steps; `matching_tests` drives the full `submitOrder` loop (both incoming sides, multi-order and multi-level sweeps, remainders, sequence numbering, a scripted replay for deterministic event ordering) and checks after each step that the book is consistent, uncrossed, and in sequence order within each level. `cancellation_tests` covers `cancelOrder` on both sides (only/oldest/middle/newest/partially filled orders, unknown and repeat IDs, aggregates, empty-level erasure, best-price transitions) and compares full captured before/after `BookState`s, including each surviving order's address, to show that unrelated state and FIFO positions are untouched.
- `submission_tests` covers submission acceptance and rejection: duplicate active IDs, reuse of cancelled and fully filled IDs, malformed orders (built by corrupting fields through `OrderBookTestAccess`, since the `Order` constructor refuses them), fully and partially filled incoming orders, multi-level sweeps, and `activeOrderCount` through a scripted sequence of events. Every rejection compares full captured before/after `BookState`s (levels, aggregates, order addresses, index, next sequence and trade IDs).
- `event_tests` checks the exact event vector each command returns: one `OrderRejected` for a refused submission; `OrderAccepted` (with the submitted, not post-fill, quantity) then one `TradeExecuted` per match in price-time order, with no resting event; only `OrderAccepted` from `addOrder`, which throws rather than rest a crossing order; one `OrderCancelled` with the remaining quantity or one `CancelRejected`. It also replays a scripted sequence of submits, adds, and cancels on two fresh books against a hand-worked stream. `event_format_tests` checks the printer's one-line text per event.
- `invariant_tests` checks `OrderBook::checkInvariants` directly. Sound books pass (scripted sessions, a level queued across a sequence wrap). Then each test breaks one structure through `OrderBookTestAccess` (an empty or misplaced level, a zero-quantity, malformed, misplaced, or reordered order, a stale aggregate, a missing, wrong, or stale index entry, a duplicate ID in one level or across sides, a crossed or locked book). Each checks the exact violation, side, price, order ID, and expected/actual values, plus that the checker stops at the first violation and how results are formatted. `testLevelOrdering` and the first pending-stop cases reach into the array through `OrderBookTestAccess`, since a level array is sorted only by how it is built. `invariant_boundary_tests` breaks a level's aggregate, runs the command named on its command line, and should abort there; `cancelOrderThrows` instead breaks an index entry so `cancelOrder` throws, and checks the boundary still aborts as the exception unwinds. It turns the expected `SIGABRT` into a normal exit (CTest otherwise fails any test killed by a signal), and CTest passes it on the abort message (`PASS_REGULAR_EXPRESSION`) and reports it Skipped in builds without automatic checks.
- `scenario_tests` runs longer command sequences through the public API, checking the whole book after every command: alternating buys and sells, hundreds of orders at one price and hundreds of levels per side, repeated partial fills of one maker, every order cancelled (and each cancel repeated) against a captured expected `BookState`, resubmission after cancellation (it loses time priority), emptying one side, refused commands mixed into a script (each leaves the book unchanged, and dropping them changes nothing else), maximal prices, IDs, and quantities, level aggregates at and beyond one `Quantity`, sequence and trade-ID wraps, and a 3000-command seeded script (its own LCG, so it is the same on every platform) replayed on fresh books with identical outcomes, checked against a ledger that follows each order's open quantity through the events alone.

## Conventions

- The hand-written consistency helpers (`expectBookConsistent`/`expectIndexConsistent`) also assert `checkInvariants().isValid()`. A test that corrupts state on purpose must undo the corruption before calling one, and must not call a public command while the book is still corrupted: with automatic checks on, the command's boundary aborts. `execution_tests`' corrupted `consumeLevel` case therefore runs only when `invariantChecksAfterCommands` is false (e.g. Release).
- `tests/allocation_failure_test.cpp` replaces global `operator new` to fail each allocation in turn and checks the book stays consistent (e.g. `addOrder` and a resting `submitOrder` roll back, a six-trade sweep that outgrows the result's inline storage leaves every execution made standing and no remainder resting). It also pins that `cancelOrder` never allocates, whether it cancels an order or refuses. MSVC Debug builds' checked iterators allocate inside `noexcept` container members, so there it exits 77 and CTest reports it **Skipped**; run `cmake --build build --config Release` and `ctest --test-dir build -C Release` to exercise it.
