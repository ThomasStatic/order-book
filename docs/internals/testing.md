# Testing

Test names, build options, what each suite covers, and test conventions. The other suites are in [`randomized-tests.md`](randomized-tests.md), [`replay.md`](replay.md), and [`benchmarks.md`](benchmarks.md).

## Running tests

a hole cut within 1 MiB of the end, at 26,214 records from it, and a stop at 26,215 and at the first record of a file over 1 MiB; a hole a modelled machine crash leaves, over twenty seeds; and a crash at every step of rotation and of a start, at both durabilities: `InMemoryLogStorage::watch` saves what the drive held after each change, and each is crashed as an engine and as a machine with four seeds, recovered, held to the witness at the surviving position and to every released response's command where the promise covers it, then written on to the end and recovered again against the uninterrupted run, with some machine crash at `process` required to have torn a record; Tests labelled `threaded` (`ctest -L threaded`) use real threads: a fixed command count, never a time limit, under `RESOURCE_LOCK threads`. ThreadSanitizer and Arm CI run exactly this label. Under ThreadSanitizer alone, `tsan_control_tests` races on purpose and must report a data race, so a passing job shows the sanitizer is really looking. Clang links its ThreadSanitizer runtime dynamically, with `-shared-libsan` and an explicit path, because the static one defines `operator new`, which collides with the tests that replace it to count allocations. `tests/expect_failure.cmake` runs a program that must fail with one exit status and one message, since `PASS_REGULAR_EXPRESSION` ignores the status and `WILL_FAIL` the reason.

CMake options: `ORDER_BOOK_BUILD_BENCHMARKS`, `ORDER_BOOK_ENABLE_TSAN` (GCC and Clang only, a configure error beside ASan or on MSVC), `ORDER_BOOK_ENABLE_ASAN` (GCC/Clang/MSVC; on MSVC it strips `/RTC1` from Debug flags and copies `clang_rt.asan_dynamic-*.dll` next to each executable), `ORDER_BOOK_ENABLE_UBSAN` (GCC/Clang only, with `-fno-sanitize-recover` so a finding fails the test; ignored with a warning on MSVC), `ORDER_BOOK_WARNINGS_AS_ERRORS`, `ORDER_BOOK_INVARIANT_CHECKS` (`AUTO`, the default, checks the whole book after each public command only where `NDEBUG` is undefined, i.e. Debug; `ON` or `OFF` defines the macro of the same name as 1 or 0, PUBLIC, for every configuration).

## What each suite covers

- `execution_tests` drives single `executeOnce` steps; `matching_tests` drives the full `submitOrder` loop (both incoming sides, multi-order and multi-level sweeps, remainders, sequence numbering, a scripted replay for deterministic event ordering) and checks after each step that the book is consistent, uncrossed, and in sequence order within each level. `cancellation_tests` covers `cancelOrder` on both sides (only/oldest/middle/newest/partially filled orders, unknown and repeat IDs, aggregates, empty-level erasure, best-price transitions) and compares full captured before/after `BookState`s, including each surviving order's address, to show that unrelated state and FIFO positions are untouched.
- `checkpoint_tests` (argument: `tests/checkpoint`) covers the book image through the public API, with expected bytes from [`../checkpoint-format.md`](../checkpoint-format.md), never from `writeImage`. **Golden samples:** four books (empty; both sides with a partial fill and an owner; stops on both sides of every type; maximal values with an aggregate above one quantity) are built from commands, and `writeImage` must give the bytes of `tests/checkpoint/images/*.image`, which `tests/checkpoint/make_golden.py` writes from hand-listed records, committed `-text`, so CI on both platforms proves platform identity. **Round trips:** `writeImage(restore(x)) == x`, with every public reading equal, the restored book sound, reporting no growth and holding what the original did, for those books and for partly filled and replaced orders and reused IDs; a queue across a sequence wrap, written by hand since a book reaches one only after 2^32 acceptances, carries its numbering on and trades in queue order. **Continuation:** at every boundary of three seeded 200-command scripts (every type and time in force, stops, owners and modes, cancels, replaces, reused IDs, which the test shows reach a trade, a trigger, a prevention, a replace, an expiry, a cancel, and a rejection), the book is imaged and restored, the rest runs on both, and every result's events and the final images must agree. **Refusals:** one case or more per `RestoreErrorCode`, each changing one field of a hand-built image and checking the exact code and offset, with the invariant cases checking the `InvariantViolation` too. **Byte sweep:** each byte of that image changed three ways must be refused or restore to a sound book whose own image restores, never crash, under ASan and UBSan. **Spans:** `writeImage` returns 0 and writes nothing past every span too short. **Capacity:** `reserve(holding())` on a restored book still tops up its other level arrays, so a new level on the side that had fewer grows nothing. The sweep also requires every accepted image whose version word is untouched to write back the same bytes. `matching_path_allocation_tests` pins that `writeImage` makes no heap call, and `allocation_failure_tests` that it never allocates and that a failing `restore` leaks nothing. It links `order_book_runtime` for the checkpoint file around an image (D4a). **Golden files:** `encodeCheckpoint` must give the bytes of `tests/checkpoint/files/{resting,empty,maximal}.obckpt`, which `make_golden.py` writes with the command log generator's own XXH64, and decoding each gives back its header and image; `extended.obckpt` (format 2, a 72-byte header, two unknown sections) must decode to its image. **Round trips** of four books' images under headers at every field's extremes. **Refusals:** one case or more per `CheckpointErrorCode`, each at its exact offset, resealing the checksum so the fault stands behind one that passes, plus two files with several faults to pin the order. **Damage:** every single-bit flip of two files is refused as `BAD_MAGIC` in the magic and as `CHECKSUM_MISMATCH` at the checksum anywhere after it, and every truncation as `BAD_MAGIC`, `TOO_SHORT`, or `CHECKSUM_MISMATCH` by its length (XXH64 itself is held to the specification's vectors in `command_log_tests`). **Verify and describe:** `verifyCheckpoint` passes the goldens and reports `restore`'s fault at its offset in the file, behind a 64- and a 72-byte header, and `formatCheckpointFault`'s line; `describeCheckpoint` gives hand-written text for the resting file, still describes a bad checksum, prints the reserved fields, a non-symbol as bytes, and a missing image header as such, reads the image header past a 72-byte header, and refuses only a wrong magic and a short file; `readImageHeader` reads the stops sample and checks nothing. The CLI's own cases are `replay_cli_checkpoint_*` and `replay_cli_usage_checkpoint_*` (`replay.md`).
- `submission_tests` covers submission acceptance and rejection: duplicate active IDs, reuse of cancelled and fully filled IDs, malformed orders (built by corrupting fields through `OrderBookTestAccess`, since the `Order` constructor refuses them), fully and partially filled incoming orders, multi-level sweeps, and `activeOrderCount` through a scripted sequence of events. Every rejection compares full captured before/after `BookState`s (levels, aggregates, order addresses, index, next sequence and trade IDs).
- `event_tests` checks the exact event vector each command returns: one `OrderRejected` for a refused submission; `OrderAccepted` (with the submitted, not post-fill, quantity) then one `TradeExecuted` per match in price-time order, with no resting event; only `OrderAccepted` from `addOrder`, which throws rather than rest a crossing order; one `OrderCancelled` with the remaining quantity or one `CancelRejected`. It also replays a scripted sequence of submits, adds, and cancels on two fresh books against a hand-worked stream. `event_format_tests` checks the printer's one-line text per event.
- `invariant_tests` checks `OrderBook::checkInvariants` directly. Sound books pass (scripted sessions, a level queued across a sequence wrap). Then each test breaks one structure through `OrderBookTestAccess` (an empty or misplaced level, a zero-quantity, malformed, misplaced, or reordered order, a stale aggregate, a missing, wrong, or stale index entry, a duplicate ID in one level or across sides, a crossed or locked book). Each checks the exact violation, side, price, order ID, and expected/actual values, plus that the checker stops at the first violation and how results are formatted. `testLevelOrdering` and the first pending-stop cases reach into the array through `OrderBookTestAccess`, since a level array is sorted only by how it is built. `invariant_boundary_tests` breaks a level's aggregate, runs the command named on its command line, and should abort there; `cancelOrderThrows` instead breaks an index entry so `cancelOrder` throws, and checks the boundary still aborts as the exception unwinds. It turns the expected `SIGABRT` into a normal exit (CTest otherwise fails any test killed by a signal), and CTest passes it on the abort message (`PASS_REGULAR_EXPRESSION`) and reports it Skipped in builds without automatic checks.
- `scenario_tests` runs longer command sequences through the public API, checking the whole book after every command: alternating buys and sells, hundreds of orders at one price and hundreds of levels per side, repeated partial fills of one maker, every order cancelled (and each cancel repeated) against a captured expected `BookState`, resubmission after cancellation (it loses time priority), emptying one side, refused commands mixed into a script (each leaves the book unchanged, and dropping them changes nothing else), maximal prices, IDs, and quantities, level aggregates at and beyond one `Quantity`, sequence and trade-ID wraps, and a 3000-command seeded script (its own LCG, so it is the same on every platform) replayed on fresh books with identical outcomes, checked against a ledger that follows each order's open quantity through the events alone.
- `engine_process_tests`, `engine_end_to_end_tests`, and `engine_signal_tests` run real processes through `ChildProcess`, each engine with a fresh log directory of its own, which the command line requires (`engine_process_tests` shows a start without one is a usage error, and `engine_signal_tests` logs at `process`, so a drive flush adds nothing to a stop's timing), (`tests/process/`, library `order_book_process_testing`, which is built with the tests or the benchmarks, since the `engine` benchmark kind and the round-trip interval start the engine through it too), with the three streams piped. Every wait has a limit, and one that runs out kills the child, except `stillRunningAfter`, which kills nothing. `sendSignal` sends a POSIX signal, and on Windows `sendCtrlBreak` sends Ctrl-Break to a child started with `ownProcessGroup`, which shares this process's console in a group of its own, so nothing else hears it. `engine_signal_tests` stops a real engine with SIGINT, SIGTERM, and SIGHUP, or Ctrl-Break on Windows, each exiting 0 with its stop report. For the second stop, a client sends 32 MiB of cancels and never reads, under `--stop-grace 60s` with the high-water mark and hard limit at 1G, so the engine reads everything and owes about 19.5 MB of answers, which in an optimized Windows build the test waits to see in the engine's own log, following each file's records up to its zero tail as it is written, since a `send` returning means only that the system took the bytes, and a stop that isn't held, landing with client bytes unread, closes with a reset, which on Windows threw away the client's unread answers (#104); only that build has taken that path, and an unoptimized engine reads only as fast as its matching thread runs, over a minute in Debug, so the others don't wait; the test sends a stop, checks the engine is still running 2 s later, then sends another, which must exit 8 within 20 s. That hold, #34's way of making the second stop deterministic, is certain only on Linux. Windows can take every answer into the system, even with the client's receive buffer set small, and then the first stop rightly flushes and exits 0: on Windows CI, Release did so on every run and Debug and ASan never did. So on Windows a stop that isn't held must be that clean stop, with its report, and the client must then read one answer for every command it sent before its stream ends, which a grace of 0 fails; the test says so on stdout, and the second stop goes untested in that run. On POSIX it sends the engine SIGABRT, which must print the abort line and end it as an abort does, so the engine is shown to install the handler. It also runs itself as a child that aborts with apps/' handler installed, once on a thread holding a shard's `AbortScope` and once elsewhere, checking the line and the abort's own status, 134 or 3, and in process that `describeAbort` allocates nothing, counted by a replaced `operator new`. On Windows it takes the console it has or allocates one, and reports Skipped only if neither works. Not shown by any test: a real-signal stop before ready, exit 6, whose window recovery now gives but no test has yet held open (`engine_tests` covers it in process, and `recovery_tests` a stop mid-replay); SIGPIPE being ignored, since every socket write already passes `MSG_NOSIGNAL` and only a closed stdout would raise it; that a matching thread holds its `AbortScope`, since nothing can make a live engine abort on one; Ctrl-C, which Windows can't send to one process group; and the close, logoff, and shutdown events. `thread_placement_tests` pins and raises threads and reads the result back through the system, expecting a Linux refusal of high priority unless the process is root or its `RLIMIT_NICE` reaches 30.

## Conventions

- The hand-written consistency helpers (`expectBookConsistent`/`expectIndexConsistent`) also assert `checkInvariants().isValid()`. A test that corrupts state on purpose must undo the corruption before calling one, and must not call a public command while the book is still corrupted: with automatic checks on, the command's boundary aborts. `execution_tests`' corrupted `consumeLevel` case therefore runs only when `invariantChecksAfterCommands` is false (e.g. Release).
- `tests/allocation_failure_test.cpp` replaces global `operator new` to fail each allocation in turn and checks the book stays consistent (e.g. `addOrder` and a resting `submitOrder` roll back, a six-trade sweep that outgrows the result's inline storage leaves every execution made standing and no remainder resting). It also pins that `cancelOrder` and `writeImage` never allocate, and, counting live allocations, that `restore` failing at each allocation in turn throws `std::bad_alloc` and frees everything it took. MSVC Debug builds' checked iterators allocate inside `noexcept` container members, so there it exits 77 and CTest reports it **Skipped**; run `cmake --build build --config Release` and `ctest --test-dir build -C Release` to exercise it.
