# Randomized command tests

- **Randomized command testing** (`tests/randomized/`, library `order_book_randomized`, CLI `randomized_tests`; the model is `tests/reference/`, library `order_book_reference`, namespace `order_book::reference`, re-exported into `order_book::randomized`). This is seeded pseudorandom testing, not fuzzing; don't call it fuzzing. `RandomCommandGenerator` (`std::mt19937_64` raw output with its own unbiased `below`, never `std::*_distribution`) draws submissions and cancellations per a `WorkloadProfile` (`balanced` is the agreed 60/25/15 submit/cancel/replace (`submitPercent`, `replacePercent`, the rest cancels), 80/20 valid/invalid, 50/50 sides, near-touch prices, mostly small sizes; the others are `aggressive`, `passive`, `cancel-heavy`, `queue`, `one-sided`, `invalid-heavy`, `limits`, `immediate` (market/IOC/FOK about 60% of submissions, larger sizes), `self-trade` (95% owned by one of 2 owners, half marketable), and `stop-cascade` (stops half of submissions, one tick from the last trade), and `replace-heavy` (40/15/45)). It reads only `ReferenceBook`, an independent plain model of the book, never the engine, so a stream depends only on seed + profile + `generatorVersion`. `ReferenceBook` is its own library (built when `BUILD_TESTING` or `ORDER_BOOK_BUILD_BENCHMARKS` is on), which never touches an `OrderBook` (it uses only the public value types), so the benchmark workloads use it too: `submit(OrderRequest)` and `submitOrder(fields, markedFilled)` model the two overloads, `cancel(id)`, plus best prices, the resting and removed ID pools, `lastTradePrice()`, and `counters()`. It matches through `plan(side, limit, quantity)`, a non-mutating walk of the opposing queues order by order (never a level's aggregate, so a bug in an engine shortcut shows), then applies the plan; each order keeps its queue iterator, so a cancel is O(1). Each `Command` records its `SubmitOverload` (`REQUEST` by default; `ORDER` for every `MARKED_FILLED` fault and a per-profile `orderOverloadPercent` of valid limits, 10% everywhere; request-path valid limits are IOC at `iocPercent`, 12%, and FOK at `fokPercent`, 8% (one roll), after `marketPercent` (10%, 2% in `passive`) become market orders, IOC at `marketIocPercent` 60% else FOK; valid GTC limit requests are post-only at `postOnlyPercent` (10%, 30% in `passive`); valid requests are `MARKET` (`marketPercent` 10), `STOP` (`stopPercent` 8, IOC/FOK), `STOP_LIMIT` (`stopLimitPercent` 12; IOC 20, FOK 10, else GTC), else LIMIT, one roll; a stop price is 1..`stopNearTicks` (5) on the untriggered side of the model's last trade price (the touch before the first trade), or at/past it at `stopPastTriggerPercent` (5); valid cancels pick a pending stop at `cancelPendingPercent` (30) when stops pend; every valid request draws an owner (`ownerPercent` 50% from `1..ownerPool` 4) and always a mode (`cancelRestingPercent` 50, `cancelIncomingPercent` 25, else `CANCEL_BOTH`); faults include `STOP_GTC`, `POST_ONLY_STOP`, `MISSING_STOP_PRICE`, `STOP_PRICE_ON_LIMIT`, `DUPLICATE_ACTIVE_ID` drawn from resting and pending IDs, `INVALID_STP_MODE`, `POST_ONLY_NOT_GTC_LIMIT`, `MARKET_WITH_PRICE`, `MARKET_GTC`, `UNSUPPORTED_TYPE` (`4 + below(6)`, past every planned enumerator), and `TYPE_CANNOT_REST` (a valid non-`LIMIT` type through the `Order` overload); and the `INVALID_TIME_IN_FORCE` fault draws a value past every planned enumerator), and `applyCommand(model, command)` applies it through the matching overload. `CommandReplayer` runs each command against the book and the model, then checks, in order: an unexpected exception, `checkInvariants` (skipped when `invariantChecksAfterCommands`, since the command's boundary has just run it), `BEHAVIOR_VIOLATION` (properties judged from the engine's own result and book alone, segment by segment through the cascade, so a misreading the model shares still fails: no market, IOC, FOK, or `STOP` order rests, and an unfilled one ends its segment with its `OrderExpired`; a FOK trades all or nothing; a post-only order never takes; no two orders of the same nonzero owner trade, judged from a `RequestLedger` of accepted requests; no stop pends past the last trade price; the model's plan steps can be preventions, it discards an unfilling FOK's plan whole, and it runs whole cascades with three ID pools, resting, pending, and removed), the exact result and events against the model's prediction, and every level and FIFO queue, then the pending stops (`findPendingStop` per model ID, `pendingStopCount`) and `getLastTradePrice`, against the model. `PROPERTY_VIOLATION` stays for caller-supplied checks, and `POOL_VIOLATION` ends a stream: `NodePool::check()` must find every free list sound and its live blocks exactly what the book holds, one per resting order, pending stop, and level, plus what an empty list takes on this platform (`blocksPerEmptyList`, measured rather than assumed), so a leak or a double free fails there. `ReferenceBook` also keeps its peaks (`peakRestingCount`, `peakPendingCount`, and `peakLevelCount`, the most on one side, stops or not), tracked at each insertion so what a cascade holds only inside a command counts, for the benchmarks' capacity. It stops at the first failure; `CommandRecorder` then holds the executed prefix, which is saved and shrunk (`shrinkFailingStream`, ddmin to a 1-minimal stream) to `--out-dir`, and `formatFailureReport` prints seed, config, command index, command, failure, book/model state, preceding commands, and replay lines. With automatic checks on, the engine aborts first; `abort_reporter` then prints seed, command, and a reproduce line, and a Release / `ORDER_BOOK_INVARIANT_CHECKS=OFF` build gives the full report and shrinking. `randomized_harness_tests` pins a fingerprint of each profile's output (now under `generatorVersion` 9): any change to what the generator draws or to a profile must bump `generatorVersion` and re-pin. It also checks, on the model alone, that each profile reaches its own target behavior within 2000 commands (`testProfilesHitTheirTargets`); a new profile needs a target there. Make each random draw in its own statement, never as two arguments of one call or two operands of one operator other than `&&`, `||`, `?:`, or `,`: their evaluation order is unspecified, so the stream would differ between compilers (GCC and MSVC evaluate arguments right to left, Clang left to right). Saved streams (`tests/randomized/regressions/*.txt`, replayed by `randomized_regressions`; still `format 1`, each new field printed only when it differs from its default, e.g. `overload=ORDER`) are the durable regressions; the seed list in `randomized_main.cpp` is valid only for its generator version. `submitOrder`, `cancelOrder`, and `replaceOrder` (`CommandType::REPLACE`; valid replaces pick a resting order and split 30/10/35/15/10 into decrease, instructions only, price change, increase, and post-only at the opposing best; faults are zero ID, price, or total, invalid mode, unknown, removed, a pending stop, and a total at or below what has executed) are generated, not `addOrder`. `ModelOrder` carries its `total`, so executed = total − open. `OrderBookTestAccess` is defined once, in `command_replayer.cpp`; don't define another in a file linked with `order_book_randomized`.

- **The engine harness** (`tests/engine/`, library `order_book_engine_testing`, CLI `engine_randomized_tests`, on `--seed` or `--explore`) runs generated commands through the real `checkEntry` and `Shard`, in one thread. `generateEngineStream` makes the whole stream first, on the models alone, from one unchanged `RandomCommandGenerator` and `ReferenceBook` per instrument, chosen by the interleaver: instrument 0 uses the run's seed, so a one-instrument run is exactly today's stream, and every instrument's IDs start at 1, so a leak between books shows. `convertForEngine` turns each command into what can reach the engine: a valid `Order` becomes its identical GTC limit request, `MARKED_FILLED` and `TYPE_CANNOT_REST` are dropped, and a mode with no owner is cleared, as the wire does. `symbolFaultPercent` adds an unknown or a malformed symbol, which must be refused with no book event. `rawCommandOf` gives the bytes a client would send, faults included. Then `runEngineSeed` checks each command: what entry rejects must be the model's own event, and what it passes runs on the shard, whose events must equal the witness's and the model's, and whose book must equal the model. A **witness** per instrument runs through the by-value overloads at a large capacity, while the shard's book runs through the `out` overloads at capacity 1, so every comparison also shows capacity changes no outcome. A run ends on `Shard::checkInvariants`, both books against the model, `compareBooks` for what the model can't see (the next sequence number and trade ID, and each resting order's own numbers and owner), and `checkBookPool` on both. `plantDivergenceBefore` gives a shard's book an order nobody else knows of, and `cancelPlantedOrder` then removes it, leaving only the numbers it used, which `engine_harness_tests` uses to show both failures are caught. `engine_randomized_seeds` is 12 seeds at 8 instruments and 5,000 commands, under `uniform` and `skewed`. Engine actions and saved streams come with the log.
- **The interleaver** (`tests/reference/interleaver.hpp`, in `order_book_reference`, so tests and benchmarks share one) chooses whose command comes next when several instruments run. Each instrument keeps one unchanged generator, so `generatorVersion` stays 9 and no fingerprint moves, and the interleaver has its own seeded source, so one instrument's commands never depend on another's. `Spread::UNIFORM`, `SKEWED` (Zipf with exponent 1, instrument `k` weighing `2^40 / (k + 1)` in whole numbers, so instrument 0 of 32 takes about 25%), and `ONE_HOT` (every command is instrument 0's, a test spread). It follows the generator's rules: raw `std::mt19937_64` output, its own unbiased `below`, no `std::*_distribution`, and no floating point. `interleaver_tests` pins each spread's first draws and fingerprints, worked out apart from this code, and a new spread needs a target check there, as a new profile does.
