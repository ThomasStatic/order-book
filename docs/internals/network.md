# Network library

Library `order_book_network` (namespace `order_book::network`, headers in `include/order_book/network/`, sources in `src/network/`), linking `order_book_runtime`. It is not public API: its contract to the outside is [`../wire-protocol.md`](../wire-protocol.md). Terms are in `GLOSSARY.md`, and the decision in ADR 0012. So far it holds the pure half, with no sockets and no threads.

- **Shared with the log.** A `Command` frame's body is bytes 4 to 39 of a log record. `replay::packCommandBody` and `replay::unpackCommandBody` in `command_log.hpp` are the one place those fields are read or written, and `RawCommand` is unchecked, because the log and the wire must report the same bad byte differently. Reusing the layout saves no copy at runtime: it saves a second field table and a second set of value mappings. `little_endian.hpp` holds the byte helpers both use.
- **`FrameReader`** (`wire_codec.hpp`). Built for a `FrameSource`, the side whose frames it reads, since the two sides differ: a reader of a client's frames accepts only `Hello` then `Command`s of the exact length, and a reader of the engine's frames skips an unknown type and trailing bytes. `feed` appends to one buffer, first dropping what `next` has taken, and `next` returns a `Frame`, `NeedMore`, or a `FrameError`, which sticks. It waits for the whole 12-byte header before judging anything, so a chunk boundary can't change an error or its correlation, then judges the header at once, so nobody waits for a body that would be refused. The checks run in the order length under 12, then type and `Hello` order, then flags, then exact length, then the body: magic, version, the reserved bytes, and for a `Command` the command byte and its unused fields. A `Frame`'s `body` is a view, good until the next `feed` or `next`.
- **Encoders and decoders.** `encodeEvent` and the rest never allocate or throw, and return 0 if the frame doesn't fit, writing nothing. `decodeEvent` returns nothing for a frame this release can't read, rather than a wrong event: a reason code it doesn't know, or a side or symbol that isn't one. It exists for the client and the tests, and it checks the frame is an event first, since other frames' bodies are too short for a symbol.
- **Values.** `FrameType`, `ProtocolError`, and `RefusedCode` carry the document's numbers, and `reasonCode` and `reasonFromCode` map `RejectionReason` through a switch, never its enumerator values. `wire_codec_tests` pins all of them.
- **`checkEntry`** (`entry_check.hpp`). Pure, in the gateway thread, after `FrameReader` has passed the frame's shape. Each byte maps to its enumerator or to `unknownValue`, past every enumerator, so the check itself is the book's own `malformedReason` and can't disagree with it. An `EntryAccepted` carries the `BookLocation` and a decoded `Command`, an `EntryRefused` a code, and an `EntryRejected` the event to send. `encodeLogRecord` requires what `checkEntry` passes, which `entry_check_tests` proves on random bodies.
- **Tests.** `wire_codec_tests` takes `tests/wire` as its argument. Golden frames come from the standalone `tests/wire/make_golden.py`, marked `-text`, so expected bytes never come from the encoder, and passing on Linux and Windows proves platform identity. It covers every frame's bytes and size, every event's round trip, one case per protocol error, every split point and small chunks of both sides' streams, a byte sweep under the sanitizers, and no allocation per frame on a warm reader. `entry_check_tests` asks a real `OrderBook` about 200,000 seeded bodies, reading the bytes its own way.
